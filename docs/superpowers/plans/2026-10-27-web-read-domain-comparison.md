# 웹 읽기 도메인 비교 계획

**목표:** 동일한 실험 Worker에서 workers.dev와 aka.page 도메인의 웹 읽기 동작 차이를 확인합니다. 임의 검색어로 Chat 모드에서 실제 자료를 읽을 방법을 찾는 연구의 한 단계이며, 별칭 배포만으로 해결됐다고 판단하지 않습니다.

**구성:** 기존 Worker에 `web-read-lab.aka.page` custom domain을 추가하고 workers.dev도 유지합니다. 코드, 가상 데이터, Durable Object 관측 기록은 그대로 공유합니다. 새 호스트는 DNS 사전 조회에서 기존 레코드가 발견되지 않았습니다. 운영 MCP와 원본 API는 변경하지 않습니다.

**기술:** Cloudflare Workers, Wrangler, 기존 GitHub 배포 workflow.

- [x] 기존 코드와 관측 결과, 빈 DNS 조회 결과를 확인합니다.
- [ ] Wrangler 설정에 custom domain만 추가하고 기존 실험 회귀와 필수 검사를 수행합니다.
- [ ] PR 검사 후 병합하고 기존 배포 인증으로 배포합니다. 인증 권한이 부족하면 실제 오류에 따라 다음 조치를 선택하며 다른 프로젝트 인증은 사용하지 않습니다.
- [ ] 두 호스트에서 각각 새 실행번호의 HTML과 쿼리를 직접 open합니다. 읽힌 문서의 링크 ID를 통한 click도 별도 조건으로 비교합니다.
- [ ] 일반 HTTP 대조군 전에 관측 로그를 보관합니다. 실패, 도착 여부, 생성번호, 생성시각을 기록합니다.
- [ ] 도착하지 않은 요청은 웹 도구 내부와 Cloudflare 앞단 중 어디서 실패했는지 미확정으로 남깁니다. 한 호스트의 성공을 모든 임의 검색의 성공으로 확대하지 않습니다.

## 사전 관측

2026-10-27 별도 Codex 실행에서 `web_search="live"` 설정을 확인했습니다. 새 HTML 및 쿼리 주소는 접근 오류와 Worker 도착 기록 0건이었고, example.com은 성공했습니다. 같은 주소의 일반 HTTP 응답은 200입니다. 설정 전환만으로는 해결되지 않았습니다.

이어 새 실행번호 `62f4ed99-fe59-48c9-8f65-6ed8ba6455d6`에서 직접 open은 실패했지만 같은 HTML·쿼리 링크의 click은 성공했습니다. 00:25:05 UTC의 새 응답 생성번호가 서버 기록과 일치했습니다. 링크가 문서에 보였다는 사실만으로 직접 open 성공을 보장하지 않습니다.
