# 올리브영 운영 중계 Safari 전환 설계

2026-11-05. 사용자 요청은 수동 작업뿐 아니라 현재 Mac의 운영 Chrome도 Safari로 전환하고 기존 Chrome 및 연계 실행을 종료하는 것이다. 과거의 운영 Chrome 유지 방침을 이번 범위에서 대체한다.

## 변경 범위

공개 Worker, MCP 10개 계약, CLI, Tunnel 주소, 인증, 누적 quota 원장은 유지한다. 올리브영 로컬 중계의 실행부만 Safari 전송으로 추가하고 기존 큐·합치기·캐시·소비자 및 전체 한도·오류 구분은 유지한다. 성공 후 운영 Chrome 전용 숨김 도우미와 Chrome guard 자동 실행을 중단한다. 범용 사용자 Chrome과 다른 프로젝트 프로세스는 실행 출처를 확인해 별도로 정리하며 이름만으로 일괄 종료하지 않는다.

## 선택지

1. Safari 작업창 상시 점유: 원본 요청 시작은 빠르지만 수동 Safari 작업과 단일 페이지 규칙이 충돌한다. 채택하지 않는다.
2. 요청 시 단일 작업 잠금을 획득하고 소유 창 생성·조회·정리: 공유 Safari를 종료하지 않고 다른 작업과 직렬화한다. 권장한다. 준비 비용과 잠금 대기 때문에 기존 18초 예산 검증이 필수다.
3. 별도 WebDriver/확장: 사용자 로그인 컨텍스트와 설치 조건이 달라지고 현재 스킬 단독 방향에 맞지 않는다. 채택하지 않는다.

## Safari 실행 계약

고정 PID/창 ID, 최소화 상태, 탭 하나와 글로벌 잠금을 확인한다. 개인 탭을 채택하지 않는다. robots.txt 같은 고정 올리브영 원점에서 허용 목록의 fetch만 실행한다. 비동기 결과는 난수 요청 식별자로 분리하고 고정 DOM 상태만 제한적으로 읽는다. 임의 URL·쿠키·개인 저장소 조회는 금지한다. 응답은 기존 2MiB 상한, fetch 15초, 유한한 외부 watchdog으로 제한한다. timeout 후 같은 세션에 겹쳐 재실행하지 않는다. 회수가 불확실하면 새 창 생성 대신 오류와 복구 필요 상태를 반환한다.

중계가 busy/잠금 점유 상태이면 정상 품절이나 준비 완료로 보고하지 않는다. 다른 작업의 잠금을 제거하지 않는다. 공유 Safari 전체 RSS 상한으로 사용자 브라우저를 종료하지 않는다. 요청 종료마다 소유 페이지만 회수하며 개인정보와 토큰은 로그에 남기지 않는다.

## 검증 및 전환

현재 다른 작업이 Safari 잠금을 사용하므로 브라우저 시험을 시작하지 않았다. 잠금 해제 및 자원·CI 비중첩 확인 후, 기존 Chrome 중계와 해당 자동 복구·숨김 실행을 통제된 순서로 일시 중단하고 소유 Chrome 회수를 확인한다. Safari 한 페이지로 상품 검색·메타·매장·실제 재고·오특 조회를 시험한다. 원본 차단·업무 오류·수량 미확인을 구분하고 응답 시간 및 반복 정리 상태를 측정한다. Safari 미지원·원본 차단·예산 초과이면 Chrome 경로를 복원하고 전환 실패로 기록한다.

성공하면 전송부 단위 회귀와 필수 저장소 검사를 순차 실행한다. 검증된 파일만 로컬 운영 runtime에 반영하고 OY_RELAY_TRANSPORT=safari로 변경한다. Tunnel·인증·원장은 보존한다. 기존 Chrome 자동 기동 및 숨김 도우미를 비활성화하고 잔존 소유 프로세스가 없는지 확인한다. 실제 캐시 우회 운영 조회와 CLI/MCP를 순차 확인한다. 로그인 후 자동 기동과 실제 Mac 재부팅 검증은 구분한다.

## 현재 미확인

Safari의 올리브영 원본 접근 허용 여부, 최소화 fetch 지연, 새 창 준비 포함 응답 예산, LaunchAgent의 Apple Events 권한, 중단·재기동 회수 및 다른 수동 작업과의 공정한 잠금 공유는 아직 실험하지 않았다. 수동 Safari 입력 성공을 운영 전환 성공으로 간주하지 않는다. 캡처는 전환 조건이 아니다.
