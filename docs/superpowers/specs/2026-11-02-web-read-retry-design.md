# 웹 읽기 재시도와 접수형 조회 검증

사용자는 2026-11-02 실제 ChatGPT 임시 채팅의 첫 실패 뒤 캐시 재시도 실험, 완성 URL 복사 재전송 안내, 문서 정합성 수정 및 효과가 확인된 접수형 조회의 운영 반영을 승인했다.

## 실험 설계

기존 독립 Worker의 가상 데이터만 사용한다. 새 실행번호별로 매번5초 지연, 최초5초 후 결과 저장, 즉시접수 후 실제 결과 링크를 비교한다. Chat 질문에 최종 주소를 제공하여 URL 출처 문제를 먼저 통제하고, 같은 주소 재시도와 실제 링크 이동을 구분한다. 현재 데이터·requestId·jobId와 서버 관측 시각을 대조한다. 모든 응답 HTML은 no-store이며 저장 결과의 재사용과 OpenAI의 사본을 구별한다. 접수는 성공/재고로 표현하지 않는다. pending 링크의 반복 횟수는 제한한다.

## 구현 경계

실험 상태는 실행번호별 Durable Object에 보관하고24시간 뒤 삭제한다. 고정5초 작업만 처리하며 외부 URL/실제 재고/자격증명을 받지 않는다. 첫 클라이언트 연결이 끊겨도 예약 알람으로 작업 완료를 보장하는지 실제 관측한다. 기존 JSON API·공개 MCP10도구·중계·원장은 변경하지 않는다.

완성 URL이 있는 복사용 문장은 `아래 주소를 웹 URL 열기 도구로 직접 열어 실제 결과를 확인해주세요: {현재 조회 조건의 정확한 공개 URL}` 형식으로 제공한다. 접근 거절과 TimeoutError를 구분하고 단순 허용 문구나 URL 일부 제공을 대체로 안내하지 않는다. 문서의 웹 전용 URL 조합 지침을 실제 링크 우선으로 맞춘다.

## 운영 반영 기준

실제 Chat 웹에서 접수 응답 및 후속 결과의 새 ID가 일치하고, 반복 표본과 실패 대조를 확보한 뒤 기존 Worker의 한도·권한·캐시를 그대로 사용하는 제한된 조회 흐름을 검토한다. 실험 성공만으로 운영의 느린 원본·캐시·중단·오류 보존을 보장하지 않는다. 확인되지 않으면 실험 기능과 문서 개선만 배포하고 이유를 기록한다. 운영 접수형 구현은 별도 회귀·리뷰·필수 CI 이후에만 배포한다.
