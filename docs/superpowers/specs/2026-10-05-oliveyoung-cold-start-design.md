# 올리브영 브라우저 준비 중 요청 만료 방지

사용자가 재고 점검 후 올리브영 오동작 방지를 요청해 앞서 제안한 준비·대기 처리 보강을 진행합니다.

## 재현 근거

운영 inventory는 find-store와 product-search를 동시에 중계합니다. 2026-10-04 23:59 UTC 원장에서는 첫 find-store가 브라우저 준비와 함께 35.1초 후 성공했지만 뒤따른 product-search는 30초 대기 상한을 넘겨 실행하지 않고 503을 반환했습니다. 같은 요청은 준비 후 2.4초에 성공했습니다. 분당/일일 쿼터 소진이 아닙니다.

## 선택한 변경

현재 Worker의 중계 조회 기본 예산은 60초, 브라우저 API 작업 watchdog은 18초입니다. 대기 상한은 40초로 조정해 관찰된 준비35초를 수용합니다. 준비된 세션의 후속 작업을 기준으로 대기40초와 API watchdog18초를 기본 예산60초 안에 배치합니다. 추가 세션 준비와 회수까지 포함한 전체 응답시간 보장은 아닙니다. 대기 만료를 검사하는 두 위치가 같은 상수를 사용합니다. 취소 요청은 그대로 실행하지 않고, 슬롯8·소비자·분당/일일 상한·캐시·직렬 브라우저 실행을 유지합니다. 대기시간을 무한히 늘리거나 일반 오류를 성공/재고0으로 바꾸지 않습니다.

35초 준비 후 다른 operation이 성공하는 테스트, 정확히40초 대기 만료 및 미실행, 만료된 합류자와 유효한 합류자가 결과를 나누어 받는 테스트, 취소 요청 및 준비 실패가 성공 캐시에 들어가지 않는 기존 테스트를 확인합니다. 수명 상태의 reason은 마지막 실패 기록이라는 점을 문서화하며 ready 판정 변경은 별도 근거 없이는 하지 않습니다.

전체 check·coverage100%·build와 명세/품질 리뷰 후 draft PR로 제시합니다. 검증한 스크립트 하나를 기존 Mac 중계에 원자적으로 반영합니다. 이전 내용의 해시 일치와 유휴 상태를 확인하고, 백업을 보존한 뒤 정상 종료·재기동과 실제 재고 조회를 검증합니다. Worker 배포나 전체 runtime 교체는 필요하지 않습니다. 다이소는 현재 판매상품과 원본 대조로 진단하고 GS25 인증키와 Cloudflare 출발지 차단은 조사 결과를 별도로 기록합니다.
