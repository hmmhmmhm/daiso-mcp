# 첫 무설치 조회의 링크 왕복 축소

사용자는 첫 사용 약2분의 원인 확인, 개선, 실제 ChatGPT 재검증을 승인했다. 기존 운영 안정성/정확도/공개MCP10개/JSON·CLI 계약을 유지한다.

## 근거

직전 동일 계정 새 임시 대화의 브라우저 진입 포함116.9/146.7초. 공식 루트 실험의 상품 HTML04:08:19.517UTC와 재고 HTML04:09:23.528UTC 사이64.011초. 같은 조건의 일반 HTTP JSON 대조는 상품1.500초/재고2.077초였다. 현재 한글 입력은 글자마다 초성→중성→완성3번 이동하므로 지갑2글자+강남역3글자에만15번 필요하다. 모델의 내부 처리 시간을 직접 측정한 것은 아니며 왕복 구조를 병목 후보로 검증한다.

## 선택

임의 URL 조립은 기존 접근 거절이 재현되어 기본 경로로 복원하지 않는다. 전체 한글 음절을 한 페이지에 나열하면 응답 크기·링크 누락이 커진다. 기존 실제 링크 계약 안에서 흔한 상품 검색어와 지역을 통째로 선택하도록 줄인다. 새로운 검색/재고 API나 고정 상품ID/수량을 추가하지 않는다.

## 설계

- 24개 이상 일반 상품군과24개 이상 지역의 고정 입력 링크. 요청과 일치하는 선택지만 사용하며 비슷한 다른 검색어로 바꾸지 않는다. 추천은 재고나 매장 존재를 주장하지 않는다.
- 새 /browse/quick 진입점도 읽기 세션을 생성한다. 기존 /browse/read와 JSONAPI를 유지한다. 검색어 선택→실제 상품 검색→카드의 매장 지역 선택→지역 단어 링크→실제 재고로 이동한다.
- 빈 입력 화면에 빠른 선택을 먼저 표시하고 임의 입력의 기존 글자 링크를 보존한다. 선택 상품ID는 실제 응답에서 유지한다. 입력·메뉴 화면은 원본 API와 주소검색을 호출하지 않는다.
- 공통 운영 안내·README접힘 블록·상세문서·Skill을 빠른 선택 우선/불일치 시 글자 입력으로 일치시키며 안내버전을 갱신한다. 기존 이미지·구조·deprecated별칭은 유지한다.

## 검증

실제 링크만 따르는 회귀에서 시작·상품·지역선택·재고까지4번 HTML읽기로 완료되고 조회API는 상품/재고 각1번만 호출되는지 검증한다. 임의 입력·잘못된 ID·공개10도구 계약 유지. 필수 CI/Coverage100%/독립리뷰 후 병합·배포한다. 이전과 같은 자연어/공식루트 두 질문을 새 임시 Chat에서 순차 실행하고 전체시간·결과·현재안내를 비교한다. 계정/캐시/모델 변동을 기록하며 서버시간과 전체시간을 혼동하지 않는다.
