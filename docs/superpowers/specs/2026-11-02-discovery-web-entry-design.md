# 자연어 발견 이후 웹 조회 입구 설계

목표: 주소 없는 ChatGPT 첫 질문에서 최신 실행 경로를 발견하기 쉽게 하고 실제 새 임시 대화로 검증한다.

관측: 이전 동일 질문2건 실패 이후 오늘 수정 전 표본1건은45.1초에 성공했다. 실제 새 작업 결과 HTML을 별도 읽기로 대조했다. 실패의 서버 오류 원문은 없어 DNS/WAF 원인으로 단정하지 않는다. 웹 읽기 저장소 사본은 최신 원문과 달리 안내.2였고, 외부 미러 검색 결과에는 오래된 POST/셸 예제가 남아 있다.

확인한 로컬 문제: README의 주요 시작 링크는 MCP 연결 설정으로 향한다. 공식 루트는 실제 조회 링크 앞에 긴 복구 규칙을 둔다. docs/web-discovery.md에는 옛 안내 버전이 현재 버전이라고 남아 있다.

수정: README의 접힌 AI 안내·이미지·배지는 보존하고 사람에게 보이는 첫 시작 링크를 ChatGPT HTML 조회로 연결한다. 원격 MCP 연결은 병렬 선택지로 유지한다. 공식 루트는 짧은 웹 조회 설명과 실제 시작 링크를 긴 규칙/프로토콜 설명보다 먼저 제공한다. 새 도구/새 조회 API/서버 권한 변경은 없다. 현재 안내는.4로 통일하고 상세 문서는 최신 연결을 기준으로 쓴다.

검증: 링크 순서/실제 href/문서 버전 계약 회귀를 먼저 실패시킨다. 전체 CI/Coverage100%/CodeQL/리뷰 후 병합·배포한다. 같은 주소 없는 최초 질문을 새 임시 대화2건에서 직렬 실행하며 성공·실패·시간·실제 href·작업 결과/독립API대조를 기록한다. 성공을 확보해도 검색 사본과 모델 선택의 보편적 해결로 일반화하지 않는다.
