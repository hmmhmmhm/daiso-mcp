# 릴레이 호출 절감 및 추적 설계

사용자가 2026-09-29 승인한 공통 캐시/중복 합치기와 디스크 안전 로깅을 구현한다.

- OY 인증/검증 후 정규 payload 키로 캐시한다. 상품 5분, 상품 ID 10분, 매장 5분, 재고 1분. 최대 256항목 및 직렬화 16MiB. 성공만 저장한다. 동일 진행 요청을 합치며 기존 queue/body/timeout/인증 제한을 유지한다. 캐시 적중은 quota 미차감.
- quota 분/일 차단을 구분하고 Retry-After와 현재 잔여/초기화 시각을 인증 health에서 제공한다. 과거 집계는 로그에서 보존한다.
- 두 로컬 릴레이에 공통 JSONL 로깅. 서비스별 64MiB(합계128MiB), 파일4MiB, 7일. 디스크 가용2GiB 미만이면 자체 오래된 로그 정리 후 기록을 중단한다. 다른 파일은 삭제하지 않는다. 재검사로 여유 회복 시 자동 재개. 큐는256개 이하, 이벤트2KiB 이하. logger 실패가 서비스 실패로 번지지 않는다.
- 로그 필드는 고정 allowlist: 시각/요청ID/상위ID/서비스/operation/단계/상태/소요시간/캐시결과/차단사유. URL query, 요청/응답 본문, 검색어, 좌표, 토큰, 임의 에러 메시지 제외. 로그0700/0600. health에 로그드롭/기록실패/디스크중단 상태를 노출한다.
- Worker 요청 컨텍스트별 ID를 응답 및 relay 요청에 전달. 모든 REST/MCP 서비스에 경계 이벤트를 적용하고 실패는 모두, 성공은 샘플링. Cloudflare managed logs 사용, 자동 invocation 로그는 꺼 민감 query가 기록되지 않게 한다. CLI stdout은 MCP 프로토콜 보호를 위해 사용하지 않는다.
- REST OY 캐시 키는 허용 query 및 기본값 정규화. 의도적 health fresh 파라미터는 보존한다.
- 릴레이 lifecycle 시작/회전/실패와 프로세스 시작/종료 기록. 터널은 기존 cloudflared 상태와 상관관계로 조사하며 무제한 stdout 파일을 만들지 않는다.
- 실패/만료/중복/용량초과/디스크부족/재시작 보존 및 민감값 미기록 테스트. 전체 check/build/100% coverage 후 PR 검토·병합, Worker 및 Mac 두 런타임 배포와 실조회 검증.

한도 증가는 하지 않는다. fresh cache가 재고를 최대1분 지연시킬 수 있다. 디스크부족에서는 서비스 가용성과 디스크 보존을 위해 파일 로그를 버리며 health로 누락을 알린다.
