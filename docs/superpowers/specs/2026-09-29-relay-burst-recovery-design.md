# 무료 릴레이 요청 집중 및 교체 시간 개선

사용자는 Zyte를 사용할 수 없어도 계속 작동하며 사용자별 제한과 대기 만료를 줄이도록 승인했다. 구현·검증·배포까지 진행한다.

## 확인한 원인

1.2.7 이후 17:40 기준 OY 실행 221건 성공, consumer 429 137건, expired 503 3건. 503은 브라우저 교체 22~23초 동안 Worker의 15초 timeout으로 연결이 취소된 경우다. 일부는 실제 upstream 성공 후 취소로 결과를 돌려주지 못했다. 기존 consumer 사유는 동시 2개 제한과 분당 12회를 구분하지 않아 순간 충돌도 분말까지 cooldown된다.

## 선택

전역 제한을 높이거나 무제한 대기를 추가하지 않는다. 소비자 제한 완화 + 짧은 충돌 재시도 + 교체를 감당하는 제한 시간 정렬을 적용한다. 이번 개선에서는 오래된 재고를 성공으로 반환하는 새 fallback을 추가하지 않는다. 기존 캐시 정책은 유지한다.

- consumer 신규 실행 24/분. 전역 30/분·3000/UTC일, 소비자 동시 2, 전체 8슬롯, 소비자 상태 1024, 캐시 상한 유지.
- admission 진입 실패는 consumer-busy, Retry-After 1초. 실제 소비자 분당 제한은 consumer와 분말 reset 유지. 표가 가득 찬 경우도 busy로 잠시 후 재시도.
- Retry-After가 정확히 1초인 검증된 consumer-busy만 허용하며 다른 값은 cooldown에 저장하지 않는다. 검증된 consumer-busy는 해당 소비자만 cooldown, Worker는 1초 대기 후 한 번만 재시도한다. 분당/일일/consumer 제한, 403/5xx, 잘못된 헤더는 자동 재시도하지 않는다. 이전 cooldown에서 busy를 만나도 같은 전체 요청 deadline 안에서 한 번만 재시도. 명시한 timeout은 전체 시도/대기 시간을 포함한다.
- 무료 relay 기본 요청 deadline 60초, direct 기본 15초 유지. 명시적 timeout 우선. REST의 세 핸들러 및 MCP 도구의 기본값/스키마도 동일하게 맞춘다. 릴레이 큐 대기 30초까지 허용하되 전체 슬롯/예약 반환 유지. 취소와 큐 대기 만료를 각각 로그로 구분한다.
- 브라우저 안전 규칙(페이지1, 30분/200회/1GiB, 정체 확인 후 회수) 유지. 새 탭이나 병렬 브라우저를 추가하지 않는다.
- quotaReason consumer-busy를 REST/MCP·검증된 cooldown·고정 로그 분류에 포함한다. IP/본문/소비자 식별자 기록 금지.
- Zyte paid 차단 회귀를 유지. 기본 경로는 직접/무료 릴레이만 사용.

## 검증

실제 외부 조회를 대량 발생시키지 않는 가짜 시계/브라우저 테스트로 24회·25회 제한, busy 후 정상 복구, 별도 소비자 격리, 예약 반환, 23초 교체 중 취소되지 않는 timeout, 30초 큐 만료, 재시도 전체 deadline 및 횟수 상한을 검증한다. 전체 check/build/coverage100%/audit, 독립 검토, PR CI 후 Worker+맥 릴레이+패키지 배포. 실제 조회 소수와 로그/메모리/슬롯을 확인한다. 운영 감소율은 배포 후 관찰이 필요하다.
