# 올리브영 소유 브라우저 교체 준비

2026-10-11 07:29:50 UTC 이후 33회 교체의 준비 공백은 25.8–195.7초, 중앙값 44.6초였다. 원본 운영 검사의 20초 예산보다 길다. 제한 시간을 늘리거나 실패를 성공으로 분류하지 않고 정상 세션을 유지하며 후속 세션을 준비한다.

## 구조와 제한

현재 세션과 준비 후보 하나만 유지한다. 프로세스 시작 시 두 고정 마커 `browser-owner.json`, `browser-owner-replacement.json` 모두 부재를 확인한다. 감시 프로세스의 배타적 마커 생성 및 부모 IPC 단절 회수는 그대로 사용한다. 슬롯은 종료 확인 이후만 재사용하며 실행 또는 회수의 불확실성은 전체 수명을 실패 상태로 고정한다.

실행 시작 시각부터 27분 또는 API 시도 160회에 후보를 준비한다. 준비된 후보는 API 실행 사이에 교환하고 이전 소유자를 회수한다. 실행 시작부터 30분 이후 또는 API 시도 200회 이후에는 해당 세션에 새 조회를 보내지 않는다. 진행 중 API는 기존 18초 watchdog 안에서 종료한 뒤 회수하며 유휴 수명은 기존 30초 주기로 점검한다. 실패한 후보는 확인된 회수 뒤 정상 현재 세션을 보존하며 자동 준비를 무한 반복하지 않는다. 상한에 도달했거나 현재 세션이 손상된 경우 기존의 명시적 요청 기반 콜드 시작으로 돌아간다.

겹친 실행은 현재 관측 RSS가 512 MiB 이하인 경우만 허용한다. 시작 전, 후보 소유자 획득 후, 페이지 준비 완료 후 및 30초 주기로 소유자 RSS 합계를 관측한다. 1 GiB 초과 시 후보를 우선 회수하며 현재 자체가 1 GiB를 넘으면 현재도 회수한다. 이는 관측 기반 상한이며 운영체제의 순간 메모리 강제 제한이 아니다. 메모리 여유가 부족하면 콜드 교체 공백이 남는다. 후보 준비 실패나 원본 사이트 차단까지 항상 해결한다는 보장은 하지 않는다.

페이지 충돌·닫힘·팝업 회수 실패와 RSS 결과는 해당 세션에 귀속된다. 이전 세션의 늦은 결과가 새 세션을 회수하지 않는다. 종료는 준비 중인 실행 결과까지 기다리고 두 소유자 모두에 같은 회수 기한을 적용한다. 종료 시작 이후 승격 및 추가 실행을 금지한다.

## 검증

지연된 후보 준비 중 정상 요청, API 실행 중 승격 금지, 후보 실패 시 현재 보존, 두 마커의 잔존 차단, 늦은 준비 결과와 두 소유자 종료, 충돌 중 같은 후보 대기, RSS 여유 및 합계, 30분/200회 상한, 회수 실패 후 실행 차단을 단위 테스트한다. 기존 감시 프로세스의 부모 단절과 마커 해제 검증도 유지한다. 전체 검사·커버리지 100%·빌드를 수행하며 실제 운영 환경과 인증 및 quota 파일은 구현 단계에서 변경하지 않는다.
