# 지오코딩 무료 쿼터 보호와 공공 주소 DB 검토

확인일: 2026-10-13. 이 문서는 이번 구현과 공식 자료 조사, 이후 공공 주소 DB 구축안을 구분한다. 사용자는 정부 주소·좌표 자료를 아직 보유하지 않는다고 답했다. 따라서 전국 주소 DB의 적재·조회·갱신은 구현 완료 상태가 아니다. 이번 작업은 유료 API 신청이나 추가 과금 활성화, 무료 키 재발급을 통한 한도 우회를 포함하지 않는다.

## 이번 구현

주소 입력은 Kakao 주소 검색 → Kakao 키워드 검색의 정확한 주소 일치 → Naver 지역 검색의 정확한 주소 일치 순서로 보완한다. 장소명 입력은 기존 Kakao 키워드 검색 → Naver 지역 검색을 유지한다. 키워드·지역 검색은 장소 검색이므로 어떤 주소든 변환하는 지오코딩 API와 동일하지 않다. 입력과 같은 주소의 업체가 검색 결과에 있어야 주소 대체가 가능하다.

주소 비교에서는 입력한 지역 토큰을 독립 토큰으로 비교하고 도로 번호와 건물 번호의 순서를 보존한다. 서로 다른 지번·도로명 필드의 숫자를 합쳐 일치시키지 않는다. 장소명만 입력 주소와 같거나 가까운 다른 가게이면 주소 대체로 선택하지 않는다. 모든 결과는 한국 범위의 유한 위경도인지 검증하며, 정확한 결과가 없으면 `null`을 반환한다. 대체 조회에도 최초 요청의 남은 시간만 전달해 전체 시간 제한을 유지한다.

GS25는 요청 지역과 일치하는 매장 중 유효한 자체 좌표가 있는 매장을 먼저 사용한다. 요청한 지역의 좌표를 끝내 확인하지 못하면 강남 기본 좌표로 조회하지 않고 `GS25_LOCATION_UNRESOLVED`(HTTP 503)를 반환한다.

## 인증 scope와 저장 경계

외부 Kakao 요청은 `Authorization: KakaoAK …`를 사용한다. Naver 지역 요청은 `X-Naver-Client-Id`, `X-Naver-Client-Secret`를 사용한다. 보호 어댑터는 이 자격증명 배열을 SHA-256으로 해시해 scope를 만든다. 쿼터 상태 키는 `quota:<scope>:<provider>`이며 원본 키나 검색어를 포함하지 않는다. 같은 Kakao 키라도 주소·키워드 API의 차단 상태는 별도이다.

Worker의 `GEOCODE_GATEWAY` 바인딩이 있는 경로는 내부 Durable Object로 조회를 전달한다. 내부 요청에는 공급자·해시 scope·검색 파라미터·시간 예산이 들어가며 외부 인증 헤더 원문을 전달하지 않는다. Durable Object는 자체 환경의 인증 정보를 읽고 scope 일치를 검증한 뒤 외부 인증 헤더를 구성한다. SQLite-backed 저장소에는 차단 만료시각만 저장한다. 검색어·좌표·응답은 요청 처리와 진행 중 병합에 필요한 메모리에서만 사용한다.

CLI 또는 바인딩 없는 경로는 유한한 프로세스 내부 보호를 사용한다. 이 상태는 별도 프로세스와 공유되지 않는다. 요청별 취소는 병합된 다른 요청의 대기를 취소하지 않는다. 시간 예산이 다르면 병합하지 않는다.

## 부록: 정부 자료 기반 자체 주소 DB 설계안

### 자료 확보와 이용 조건

우선 후보는 [행정안전부 도로명주소 전자지도](https://www.data.go.kr/data/15050413/fileData.do)이다. 공식 목록은 전국의 건물·건물군·도로구간·출입구 등 11종을 시도 또는 시군구 단위로 제공하며, 신청서·본인확인·이용목적 심사·관할기관 승인을 요구한다. 자료는 무료이고 목록의 이용조건은 공공누리 제1유형이다. [공공누리 안내](https://www.kogl.or.kr/info/freeUse.do)에 따르면 제1유형은 출처표시 조건으로 상업적 활용과 변경이 가능하다.

이 권한은 승인받아 제공된 정부 자료에 대한 것이다. Kakao·Naver·VWorld 응답을 정부 자료처럼 적재할 권한으로 확대하지 않는다. 자료 신청 시 서비스의 주소 조회·좌표 변환·공유 조회 용도를 정확히 적고, 승인 범위와 실제 제공 파일의 이용조건을 함께 보존해야 한다. 사용자가 아직 자료를 확보하지 않았으므로 아래는 구현안이며 데이터가 적재된 운영 DB가 아니다.

### 출처와 좌표 변환

원본 파일의 배포일·자료 기준일·원본 URL·제공기관·지역·라이선스·승인 범위·파일 checksum을 기록한다. 조회 결과에는 예를 들어 “출처: 행정안전부 도로명주소 전자지도, 자료 기준일 YYYY-MM-DD, 공공누리 제1유형”을 표시하고 출처 링크를 제공한다. 라이선스 안내의 제목·제공기관·연결 조건을 실제 배포본에 맞춘다. 정부가 서비스 자체를 인증·보증한다는 표현은 사용하지 않는다.

공식 목록은 ITRF2000/GRS80와 투영좌표를 안내한다. 실제 다운로드 파일의 좌표계 정의·`.prj`·제공 명세를 확인한 뒤 WGS84 EPSG:4326으로 변환해야 한다. API의 UTM-K와 전자지도 배포 파일을 동일 EPSG로 단정하지 않는다. 입력 EPSG가 5179로 확인된 자료에만 5179→4326 변환을 적용한다. 원본 x/y·CRS를 보존하고 출력은 경도/위도 순서를 명시한다. 한국 좌표 범위·정상 기준점·왕복 변환 오차를 검증한 자료만 서비스에 사용한다.

출입구 좌표와 건물 도형 중심점은 의미가 다르다. 원본에 출입구 좌표가 있으면 좌표 종류를 유지한다. 출입구가 없어서 중심점을 계산하는 정책은 별도 표시하고, 실제 출입구라고 설명하지 않는다.

### 권장 스키마

| 테이블              | 주요 필드·키                                                                                                           | 목적                                                            |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `address_sources`   | `source_id`, 기관, 원본 URL, 라이선스, 승인 범위, 자료 기준일, 파일 checksum, 원본 CRS, 적재 시각                      | 출처·허가·자료 버전 추적                                        |
| `address_buildings` | 원본 건물 관리 식별자(수록 시), 행정구역코드, 도로명코드, 지하여부, 건물 본번/부번, 도로명주소, `source_id`, 활성 여부 | 공식 주소 단위 조회                                             |
| `address_aliases`   | 별칭 유형, 정규화된 주소, 행정구역·지번코드, 산 여부, 지번 본번/부번, 연결된 건물 식별자                               | 구 시도명·지번·도로명 별칭 연결. 다중 후보를 임의로 합치지 않음 |
| `address_points`    | 건물/출입구 식별자, 좌표 종류, 원본 x/y/CRS, 변환 경도/위도, 변환 버전, `source_id`                                    | 좌표 출처와 의미 보존                                           |
| `address_imports`   | 적재 ID, 원본 버전, 처리 건수, 변경/삭제 건수, 검증 상태, 적용 시각                                                    | 검증 후 원자적 버전 교체와 롤백                                 |

원본 제공 명세의 필드와 안정적인 식별자가 확인된 후 실제 컬럼명을 확정한다. 아직 확보되지 않은 원본의 필드 구성을 사실로 가정하지 않는다. 좌표 검색 인덱스와 원본 주소 검색 인덱스는 정부 자료에만 적용한다.

도로명 조회키는 `(행정구역코드, 도로명코드, 지하여부, 건물 본번, 건물 부번)`을 기본으로 검토한다. 지번 조회키는 원본의 법정동/리 코드·산 여부·지번 본번/부번을 분리한다. 문자열에서 모든 숫자를 단순 연결하는 키는 사용하지 않는다. 도로 번호와 건물 번호를 바꾸거나 `123-4`를 `1234`와 같게 취급하지 않는다. 행정구역 코드의 앞자리 0은 문자열로 보존한다.

입력의 시도 명칭과 공백을 정규화하되 지역 범위를 유지한다. 동일 도로명·본번이 여러 지역에 있거나 한 주소에 여러 건물/출입구가 있으면 후보를 유지하고 사용자 입력으로 구분한다. 가까운 건물 하나를 자동 선택해 정확한 주소로 표시하지 않는다. 상점명·지점명·영업시간·폐점 정보는 주소 DB에 자동으로 생기지 않으며 별도 허용 원천이 필요하다.

### 갱신과 운영

[주소기반산업지원서비스](https://business.juso.go.kr/)는 주소 다운로드와 매일 변경되는 변동자료 연계 기능을 안내한다. 적용할 자료 종류가 실제로 제공하는 배포 주기와 변경 필드를 확인한 뒤 갱신 방식을 정한다. 모든 전자지도 자료가 매일 같은 형식으로 제공된다고 가정하지 않는다.

권장 운영은 제공 가능한 변경자료를 순서대로 적용하고 월 단위 전체본과 대조하는 방식이다. 이는 서비스의 권장 갱신 정책이며 공급자가 월별 배포를 보장한다는 뜻은 아니다. 생성·수정·삭제·행정구역 개편·코드 변경을 처리하고, 변경자료 누락 시 임의 보간 대신 전체본 재동기화를 진행한다. 임시 테이블에 적재→건수·중복·좌표·식별자 검증→원자적 교체 순서를 사용하며 마지막 정상 버전으로 롤백할 수 있게 한다.

정확한 공공 DB 매칭이 되지 않으면 기존의 저장 없는 실시간 공급자 검색으로 처리한다. 실시간 응답을 공공 DB의 빈 부분을 채우는 자료로 저장하지 않는다. DB 자료 기준일·조회 출처·매칭 수준을 사용자에게 표시하고, 오래된 자료나 다중 후보는 정확한 최신 위치라고 단정하지 않는다.
