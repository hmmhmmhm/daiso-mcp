# 세븐일레븐 재고 요청 복구 (2026-10-08)

감사에서 `/api/v1/open/real-stock/multi/01/stocks`의 `storeList`가 한 점포일 때
HTTP 200을 반환하고, 두 점포 이상일 때 HTTP 400, `code: 501`,
`message: 정상적인 점포 조회 요청이 아닙니다.`를 반환하는 것을 확인했습니다.
경로 이름의 `multi`를 근거로 여러 점포를 한 요청에 넣으면 안 됩니다.

재고 클라이언트는 지역 키워드로 매장을 필터링하고 기존 거리 기준으로 정렬한 뒤
`storeLimit`에 포함된 점포만 선택합니다. 선택한 점포를 순서대로 한 곳씩 호출하며,
직접 API와 중계의 `seven-stock` 모두 `storeList: [점포코드]`를 사용합니다.
`totalStoreCount`는 제한 이전의 일치 매장 수를 유지합니다. 제한이 0이면 재고 상품
메타데이터와 재고 API를 호출하지 않습니다.

성공 수량 0은 품절이고, 누락·음수·해석할 수 없는 수량은 -1(미확인)입니다.
개별 직접 API 실패는 최초 오류 원문과 다른 점포의 성공 수량을 함께 보존합니다.
직접 API HTTP 429는 그 오류를 보존한 채 남은 점포 조회를 중단합니다.
중계의 `ServiceError`는 그대로 전파하여 쿼터·구성·상위 서비스 오류를 숨기지 않고
후속 점포 호출을 중단합니다. 클라이언트의 공개 읽기 캐시는 재고를 저장하지 않습니다.
MCP는 오류 코드 501·503만으로 암호화 실패를 추정하지 않고 RSA·복호화·암호화
문구가 실제 오류에 있는 경우에만 암호화 안내를 제공합니다. REST도 오류 메시지를 보존합니다.

Worker의 재고 캐시는 `seveneleven-inventory-v3` 키를 사용하여 기존 10분 실패
캐시를 참조하지 않습니다. `stockAvailable: true`이며 `stockError: null`인 응답만
30초 저장하고 stale 재사용은 0초로 설정합니다. 확인된 0개 재고는 저장할 수 있으나
오류·미확인 결과는 `Cache-Control: no-store`를 적용합니다.

CU·GS25·세븐일레븐 공통 중계 예산은 분당 69회, 일당 100,000회입니다.
재고 복구를 위해 이 한도를 올리거나 원장을 초기화하지 않습니다.
429 이후에는 중계가 제공하는 재시도 시간과 운영 예산을 따릅니다.
기본 재고 요청은 최대 20개 점포를 조회합니다. 상품 검색 상한 10회, 매장 검색 1회,
상품 재고 메타데이터 1회를 합치면 단일 조회의 최대 호출 수는 32회입니다.
다른 서비스와 동시 요청이 같은 예산을 소비하므로 남은 예산을 가정하지 않고
실제 중계 쿼터 응답에서 중단합니다.

`tests/services/seveneleven/inventory-bounded.test.ts`는 직접·중계 단일 점포 호출,
거리순 제한, 0·미확인 구분, 개별 실패 보존, 직접·중계 429 중단을 검증합니다.

## Mac 실행 런타임에 따른 403·502

같은 Mac, URL, 본문, 모바일 헤더로 비교했을 때 Node 24.15.0은 HTTP 403과
Incapsula HTML을 반환했으며, Node 25.9.0은 HTTP 200 JSON을 반환했습니다.
설치된 중계 검증기에 정상 JSON을 넣으면 200이므로 이 장애는 응답 스키마 불일치가
아니었습니다. 실행 버전에 따른 접근 차이는 확인했지만 TLS 지문 등 내부 차단 원인은
확정하지 않았습니다. 원본 HTML은 정상 재고로 해석하지 않으며 중계의 502로 전달됩니다.

복구 시 셸의 `node --version`만 확인하지 말고 LaunchAgent `ProgramArguments[0]`의
실행 파일로 같은 요청을 확인합니다. 인증·원장·환경 파일을 보존하고 plist를 백업한 뒤,
검증된 실행 파일로 변경합니다. 운영은 Node 25.9.0으로 바꾼 뒤 공개 재고 응답에서
`stockAvailable: true`, `stockError: null`을 확인했습니다. 이는 점검 시점의 결과이며
향후에도 특정 버전이 항상 허용된다는 뜻은 아닙니다.

변경 전 새 실행 파일로 중계 모듈을 로드해 호환성을 확인합니다. launchd는 `bootout`
후 기존 프로세스가 종료되기 전에 `bootstrap`하면 일시적으로 오류 5를 반환할 수
있습니다. 종료 상태를 확인하고 재등록한 다음 건강 응답과 CU·GS25·세븐일레븐·CGV를
확인합니다. 건강 응답 200만으로 외부 재고 성공을 판단하지 않습니다. 실행 파일이
패키지 관리자 갱신으로 사라지지 않도록 경로와 버전을 운영 기록에 남깁니다.
