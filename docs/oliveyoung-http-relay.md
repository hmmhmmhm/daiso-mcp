# 올리브영 HTTP 중계

브라우저를 실행하지 않고 맥에서 공식 조회 API를 호출하는 선택 모드입니다. 기존 REST/MCP/CLI와 중계 인증·캐시·호출 한도·원장을 유지합니다. 맥의 전원·네트워크·중계 프로세스는 계속 필요합니다. 기존 GUI LaunchAgent의 로그인 시작 조건까지 변경하는 기능은 아닙니다.

## 실행 설정

Python3 표준 라이브러리만 사용하며 별도 pip 패키지나 쿠키 파일은 필요하지 않습니다. 아래 두 값을 기존 비공개 relay.env에 추가합니다.

```sh
OY_RELAY_TRANSPORT=http
OY_HTTP_PYTHON=/opt/homebrew/bin/python3
```

Python 경로는 설치 환경에 맞춥니다. 설정을 생략하면 기존 browser 모드이며, http 모드가 실패해도 자동으로 브라우저를 띄우지 않습니다. 운영 토큰이나 개인 프로필은 Python 프로세스에 전달하지 않습니다.

## 확인할 기능

- 상품 검색: product-search-v3
- 매장 검색: find-store
- 상품 식별자 조회: stock-goods-info-v3
- 매장별 재고: stock-stores

중계 health에서 `transport: http`, `browserRequired: false`, `pages: 0`, `state: ready`를 확인합니다. ready는 실행 준비 상태이며 공식 서비스의 모든 요청 성공을 보장하는 표시는 아닙니다. 실제 상품·매장·재고도 함께 검증해야 합니다.

고정 공식 주소와 네 경로만 허용합니다. 리다이렉트, HTTP200이 아닌 응답, 잘못된 JSON/성공 형식, 응답 용량 초과 및 시간 초과는 실패로 반환합니다. 차단 HTML을 재고0으로 바꾸지 않습니다. 네트워크 읽기15초, 자식 프로세스18초, 응답2MiB 상한이며 별도 외부 요청 재시도는 하지 않습니다.

## 전환·되돌리기

원장과 비밀 설정을 먼저 권한600인 비공개 위치에 백업합니다. 진행 요청이 없을 때 기존 중계를 정상 종료하고 소유 브라우저의 종료를 확인한 뒤 코드와 설정을 반영합니다. quota.json이나 인증 값을 초기화하지 않습니다.

HTTP 조회가 차단되면 원인을 확인하고 `OY_RELAY_TRANSPORT=browser`로 변경해 중계를 재시작할 수 있습니다. 브라우저 모드에는 기존 GUI 환경과 Playwright 설치가 필요합니다. 쿠키나 브라우저 인증을 HTTP 모드에 복사하여 재사용하지 않습니다.

## 2026-10-06 실측

같은 맥에서 쿠키 없는 Python urllib는 네 API의 HTTP200/SUCCESS를 반환했고 Node fetch·Node https·기본 curl은 403을 받았습니다. Python도 필수 헤더를 제거하면403이었습니다. JSON 공백/문자 인코딩 변경은 원인이 아니었으며 정확한 차단 기준을 TLS만으로 확정하지 않습니다.

브라우저 중계와 동일 조건에서 상품 코드·상세 식별자·매장 코드·실제 재고 필드를 대조했습니다. 명동2가점 핸드크림 일반9/오늘드림7, 선크림 일반54/오늘드림43 및 픽업/취급 상태가 일치했습니다. 이 수량은 확인 당시 관측값이며 이후 변할 수 있습니다. HTTP 성공 여부는 제공자 정책·네트워크·클라이언트 버전에 따라 달라질 수 있으므로 장기간 무차단을 보장하지 않습니다.
