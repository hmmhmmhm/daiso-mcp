# 조회 오류 복구와 제한

CU의 좌표 없는 매장 키워드 조회는 공식 매장 주소의 본주소를 확인한 뒤 좌표를 얻고, 선택 상품의 실제 재고를 다시 조회합니다. 건물 번호 뒤 쉼표와 층·호수 상세를 처리하되 다른 도로명·지번이나 알 수 없는 숫자가 섞인 주소를 임의로 자르지 않습니다. REST/MCP `location`은 실제 사용한 좌표를 반환하며, 확인하지 못한 매장의 `stock`은 `null`입니다. CU 매장·재고 캐시 키 v5는 이전 미확인 수량·좌표 응답을 다시 사용하지 않습니다.

GS25의 `gs25-products`, `gs25-stock`만 HTTP 502·503·504 또는 응답 수신 전 연결 실패 때 한 번 재시도합니다. 원래 요청 시간 안에서 최대 15초를 사용하며 첫 시도에 예산의 약 절반을 배정하고 250ms 또는 원본 `Retry-After`만큼 기다립니다. 원본의 대기 안내가 남은 예산보다 길면 즉시 오류를 전달합니다. 다른 작업, 인증 401·403, quota 429, 잘못된 정상 응답은 재시도하지 않습니다. 두 시도는 각각 중계 입구를 통과하므로 두 원본 호출이면 기존 원장을 두 번 소비합니다. 정상 캐시는 원본 예산을 추가 소비하지 않습니다.

이마트24의 각 공개 HTTP 조회는 최대 두 번 시도하며, 매장 키워드 변형 전체는 같은 시간 예산을 공유합니다. 기존 15초 제한을 시도마다 새로 주던 방식 대신 시도·대기 합계에 적용합니다. 매장 검색의 여러 키워드 변형도 같은 제한 안에서 진행합니다. 알려진 공개 API의 403·408·500·502·503·504·522·524에 한정해 재시도하고, 401·429는 재시도하지 않습니다. 상품 검색 POST는 조회 작업이며 주문·예약·전송 API에는 적용하지 않습니다. 계속 실패하면 오류·부분 결과를 유지합니다.

올리브영의 `x-relay-quota-reason: consumer-busy`, `Retry-After: 1`인 429는 다른 조회가 처리 중이라는 의미입니다. 같은 소비자의 처리 슬롯·원본 호출 한도는 그대로 유지합니다. Worker는 첫 대기 1초, 이후 2초에 작은 임의 지연을 더해 최대 24번 다시 기다리며, 요청의 기존 전체 시간 제한을 넘기지 않습니다. 취소되면 대기 타이머와 요청을 중단합니다. 일일·분당·소비자 원본 한도, 인증 오류, 잘못된 응답과 이유가 구분되지 않는 503을 busy로 간주하지 않습니다. 한도를 삭제하거나 다른 소비자 이름으로 바꾸지 않습니다.

검증은 실패 후 정상 응답·지속 실패·인증/실제 quota 오류·전체 시간 경계·응답 본문 읽기·취소를 포함합니다. 외부 사이트의 오류 자체를 제거하는 방식은 아니므로, 재시도 후에도 실패하면 그 상태를 사용자에게 알립니다. 재고를 품절 0으로 바꾸거나 확인하지 못한 최신 재고를 이전 값으로 대체하지 않습니다.
