# 2026-09-10 외부 서비스 응답 개선

## 확인한 원인과 변경

- GS25 기존 매장 웹 주소는 새 GS리테일 사이트로 이동합니다. 기존 CSRF 토큰과 이중 JSON 응답 처리 대신 새 사이트가 사용하는 공개 매장 API를 연결합니다. `shopName`으로 검색하고 `posY`를 위도, `posX`를 경도로 정규화합니다. 실제 강남 검색에서 46개 매장을 확인했습니다. 공개 매장 정보는 재고 수량의 근거가 아닙니다.
- REST와 MCP 매장 탐색 모두 공개 매장 경로를 사용해 빈 기본 응답을 보완합니다. 공개 경로까지 실패하면 빈 매장 목록으로 성공 처리하지 않습니다.
- CU 재고 검색은 운영에서 JSON 대신 HTML을 반환했습니다. 정상 HTTP 코드의 HTML도 식별 가능한 오류로 구분하고 CU 응답에 `available:false`와 원인을 전달합니다. 헬스체크도 이를 정상 재고로 처리하지 않습니다. 일반 JSON 문법 오류는 그대로 실패하고, content-type이 잘못 지정된 유효 JSON은 계속 허용합니다. 확인된 오류 코드 `3000`도 정상 빈 재고로 처리하지 않습니다.
- 올리브영 전체 헬스체크의 고정 5초 제한을 제거해 요청한 제한 시간을 적용합니다. 간이 검사의 요청 제한과 지연 경고는 유지합니다. 이마트24 매장·상품 핸들러도 `timeoutMs`를 반영합니다.

## 남은 운영 제약

GS25 재고 원본은 HTTP 401과 `인증키가 제공되지 않음`을 반환합니다. 운영에 유효한 `GS25_API_KEY`를 설정해야 재고 복구를 검증할 수 있습니다. 공개 매장 API로 인증이 필요한 재고를 대체하지 않습니다.

CU는 로컬 직접 요청이 성공했지만 운영 경로의 HTML 응답 원인은 확정되지 않았습니다. 이번 변경은 실패를 명확하게 전달하며 조회 자체를 복구했다고 주장하지 않습니다. 확인되지 않은 HTML에 유료 대체 요청을 추가하지 않습니다.

이마트24 매장은 직접 검사에서 약 1.5초에 성공했다가 약 31초 후 시간 초과로 실패하고 다시 성공했습니다. 제한 시간 전달을 바로잡아도 외부 서버의 간헐 지연·403이 모두 해소되는 것은 아닙니다.

## 검증

회귀 테스트는 GS25 공개 API와 좌표 변환, CU 응답 형식·조회 불가 상태, 간이/전체 검사 제한 시간 적용을 검증합니다. 운영 반영 뒤 매장 검색 및 전체 fresh 헬스체크로 실제 복구 범위와 잔여 장애를 확인합니다.
