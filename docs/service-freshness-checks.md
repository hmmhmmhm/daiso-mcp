# 운영 헬스 체크의 캐시 우회

`GET /api/health/checks?fresh=true`를 새 원본 점검으로 실행하려면 운영 시크릿 인증과 `x-health-check-force-fresh: true`를 함께 보냅니다. Better Stack 자동 모니터 요청에는 기존 결과 재사용 정책이 적용됩니다. 인증된 새 점검은 요약 캐시와 하위 REST 응답 캐시를 우회하고, 신뢰된 원점에만 운영 인증 및 새 점검 헤더를 전달합니다. 인증되지 않은 공개 요청의 헤더로 내부 캐시를 우회할 수 없습니다.

GS25·CU·세븐일레븐·CGV는 인증된 새 점검에서 중계에 `x-relay-cache-bypass: true`를 전달합니다. 중계는 Bearer 토큰을 먼저 검증하며, 이 요청은 저장 응답이나 기존 진행 작업을 사용하지 않고 기존 동시 실행 상한·대기 기한·호출 예산을 그대로 적용받습니다. 새 점검 결과는 일반 요청 캐시에 저장하지 않습니다. 세븐일레븐 직접 상품·매장·인기 검색어 캐시와 GS25 직접 매장 캐시도 우회합니다. 디트릭스 중계에는 응답 캐시가 없습니다.

상품 검색 성공은 재고 확인 성공을 의미하지 않습니다. 세븐일레븐 재고 점검은 매장별 실제 확인 여부와 수량을 따로 검증합니다. 원본 오류가 발생한 상태에서는 과거 상품 검색 성공을 사용해 점검을 정상으로 판정하지 않습니다.

## 메가박스 지점 조회

근처 지점의 정확한 거리순 정렬에는 해당 지역의 모든 지점 좌표가 필요합니다. 반환 개수가 1개여도 좌표 조회 전에 후보를 자르면 실제 최단 거리 지점을 놓칠 수 있습니다.

일반 조회는 공식 지점 페이지에서 확인한 주소·좌표를 최대 256개, 1시간 보관합니다. 동일 지점의 진행 중 조회를 공유하고 반환 객체를 분리합니다. 오류 및 좌표 미확인 결과는 저장하지 않습니다. 상영 목록·회차·잔여 좌석은 이 캐시에 저장하지 않고 매번 원본을 조회합니다. 인증된 새 운영 점검은 정적 지점 캐시와 진행 작업도 우회합니다. 따라서 새 원본 점검의 지연은 그대로 관찰되며, 정상 판정 기준을 높여 감추지 않습니다.

## 회귀 검증

- 원본 성공으로 캐시를 채운 뒤 원본이 403을 반환하면 인증된 새 세븐일레븐 점검은 정상으로 판정하지 않습니다.
- 따뜻한 `caches.default`가 있어도 인증된 운영 요청은 GS25·CU·세븐일레븐·CGV 응답 캐시를 우회합니다.
- 토큰이 틀린 요청은 캐시 우회나 중계 예산 사용 권한을 얻지 못합니다.
- 메가박스 지점 캐시는 만료·용량·동시 요청·객체 변경·오류·좌표 누락·새 점검 우회를 검증합니다.
